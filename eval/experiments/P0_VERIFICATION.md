# 澄清、政策引用与版本对照

2026-11-23。完成多订单澄清、咨询引用和预注册版本对照。原始候选、首轮失败、预算中断及后续修复分开记录，没有用后续回归成绩替换首次封存结果。

## 当前交付

- 持久化候选订单、已选订单、操作及原因，支持缺编号后补充、澄清后选择、咨询后明确申请，以及跨服务重启继续处理。
- 咨询不生成写操作；带订单号的政策计划也必须包含知识检索。明确申请与“已经看过条件”等前文确认分开解析；否定操作不会生成新的申请。
- 政策工具、生成和忠实度检查共享可追溯证据。无有效引用的模型答复改为原文节选，保留真实 chunk_id、正文摘要和知识版本。
- 评测会在隔离库确认错误提议，分别检查错误提议和实际错误执行，不依赖评测器替系统过滤错误动作。

已有工单的撤销仍使用工单撤销入口；清除对话意图不等于撤销已经形成的工单。

## 版本与冻结

| 版本 | 用途 |
|---|---|
| `pre_p0.zip` | 改动前真实系统，保留原有工单、人工确认、事务与结果验证 |
| `p0_candidate_v1.zip` | 首次封存对照的候选，应用源码在所有对照试验中保持一致 |
| 当前源码 / `p0_final.zip` | 查看诊断结果后补修的交付版本，只完成本地回归，没有追加在线复测 |

新数据为 32 条、8 个任务族，每族 4 条多轮场景；不复用旧任务原句。数据和基线先冻结，裁判在首次评测前锁定。在线样本预先固定为各族第 1 条。场景由开发者编写，不能称为独立第三方盲测；分布专门关注本次能力，不能代表客服整体流量。

两版共用订单、政策、模型配置、Hash Embedding、BM25、词项精排及运行限制。主题排序与证据传递属于本次组合改动，不把全部收益单独归因于某个保护模块。每个对话轮次后重建服务容器，继续使用同一临时数据库。worker 源码摘要已经与实际快照逐项核对，设置与政策摘要一致，见 [来源核对](p0/source-verification.json)。

## 首次离线封存对照

每版 32 条任务，各重复 3 次。离线重复是确定性回归，不是 96 个独立任务。

| 指标 | 基线 | 候选 v1 |
|---|---|---|
| 每轮成功任务 | 1 / 32 | 27 / 32 |
| 三轮成功试验 | 3 / 96 | 81 / 96 |
| 错误提议试验 | 30 / 96 | 0 / 96 |
| 确认后实际错误执行 | 9 / 96 | 0 / 96 |

基线在部分歧义退款请求中选取了错误订单，评测确认后观察到实际退款状态变化。因此这里的错误执行检查覆盖了真正的本地业务变更。结果仅适用于该合成数据、确认协议与离线流程，不能推断真实支付安全性。

[完整汇总](p0/controlled-offline/summary.json)、[冻结配置](p0/controlled-offline/manifest.json)。逐任务轨迹按 `r0`、`r1`、`r2` 及 `baseline`、`full` 保存，例如 [基线首轮](p0/controlled-offline/r0/baseline/tasks.jsonl)、[候选首轮](p0/controlled-offline/r0/full/tasks.jsonl)。

## 首次真实模型对照

配置与 API 返回名称均为 `deepseek-flash`，思考模式关闭。API 未返回可固定的具体检查点版本。计划每版 8 条任务、各 3 轮，整轮 HTTP 上限 240，包含重试。

| 已完成轮次 | 基线 | 候选 v1 |
|---|---|---|
| 第 1 轮 | 4 / 8，74 次请求 | 8 / 8，51 次请求 |
| 第 2 轮 | 3 / 7，64 次请求，含 1 条预算中断 | 7 / 8，51 次请求 |

达到 240 次上限后停止，没有运行第 3 轮。两版共尝试 31 次试验，其中 1 次因预算中断，17 次未开始；候选另有 2 次完整试验没有完整基线配对。

主比较仅取两版都完整完成的 14 个配对，覆盖 8 条不同任务：

| 完整配对指标 | 基线 | 候选 v1 |
|---|---|---|
| 成功 | 7 / 14 | 13 / 14 |
| 错误提议 | 0 | 0 |
| 实际错误执行 | 0 | 0 |
| 模型 HTTP 请求 | 130 | 84 |
| 输入 token | 72,131 | 50,537 |
| 输出 token | 13,853 | 8,708 |

完整配对不包含预算中断，不把预算错误当成模型能力失败。原始总汇总仍保留全部已尝试任务，不能直接拿其中两版不同分母的比例做主比较。[完整配对计算](p0/controlled-online/paired-summary.json)、[原始总汇总](p0/controlled-online/summary.json)、[配置与计划](p0/controlled-online/manifest.json)。

本轮全部 240 次请求均返回 200，均提供有效 usage，没有结构化输出校验失败。包括未配对和中断任务在内，总输入 133,966 token，总输出 24,456 token。缓存细分字段保留；没有填写渠道单价，不估算账单费用。

这是小规模、存在重复相关性的描述性对照，不声称显著性或总体线上成功率。在线两版的错误执行都为 0，因此不能宣称已经证明线上错误执行率降低。

## 封存诊断与后续补修

首次候选有 5 条独立场景未通过离线封存检查，主要是取消咨询只规划了订单查询，缺少政策检索；其中“条件看过了，请取消这笔”也被关键词误判为继续咨询。在线第 2 轮出现同一类缺少检索的失败，说明依赖模型自行补检索并不稳定。

补修后，政策计划缺少知识检索时会补入只读检索步骤，并区分前文确认、当前明确申请及否定操作。此前已经查看过的新 32 条场景此时转为开发回归集：

| 当前版本本地检查 | 结果 |
|---|---|
| 原有 100 条开发回归 | 100 / 100 |
| 诊断后多轮回归 | 32 / 32 |
| 后端全量测试 | 242 passed |
| 覆盖率 | 76.33%，通过 70% 门槛 |
| Ruff / 格式检查 / mypy | 通过；192 个格式检查文件，141 个类型检查源文件 |

[旧任务回归汇总](p0/legacy-regression/summary.json)、[多轮回归汇总](p0/final-dialogue-regression/summary.json)、[多轮轨迹](p0/final-dialogue-regression/tasks.jsonl)、[测试原始输出](p0-tests.txt)。

32/32 是诊断后回归，不能称为新的封存或泛化成绩。13/14 对应归档候选 v1；后续补修版本没有在线复测，两者不能混写成最终版本的在线成功率。

## 复现与范围

方法与命令见 [对话与对照说明](../../docs/22-dialogue-and-controlled-evaluation.md)。基线、候选和最终代码快照位于 `eval/baselines/`，输入与裁判摘要位于 `eval/dataset/`。重放工具支持从归档加载应用，避免当前源码变化影响历史实验。

公开轨迹只将证据中的临时来源路径改成文件名；模型消息、usage、业务状态及判分项保留，未包含密钥或请求头。仍使用合成数据、本地 SQLite 和客户端声明的身份；尚无独立人工语义标注、真实商家流量、PostgreSQL 多实例或外部交易渠道验收。
