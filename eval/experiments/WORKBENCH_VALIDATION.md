## 工单场景

| 场景 | 断言 |
|---|---|
| 重建服务后确认 | 待审核动作、历史正文和订单快照可读取，操作正常完成 |
| 提交后响应丢失 | 重试取得相同结果，业务操作只有一条审计记录 |
| 四个并发确认 | 全部读取完成状态，业务写入只执行一次 |
| 不同用户或会话 | 无法读取或确认该动作，原订单保持不变 |
| 订单状态变化 | 进入重新审核，原状态与复核时状态均有记录 |
| 发布新政策 | 拒绝旧建议，原知识版本及证据正文保留 |
| 过期或撤销 | 不执行业务动作 |
| 工具写入后异常 | 订单和审计记录回滚，再次复核后可重试 |
| 取消时意外新增退款 | 业务验证失败，取消与错误退款记录一起回滚 |
| 提交前模拟中断 | 整个事务回滚，工单保持待审核，可再次确认 |
| 退款或退货重复确认 | 只新增一条相应申请，金额、原因与状态匹配 |
| 无关候选证据 | 不生成可直接执行的确认动作 |

## 验证范围

上述场景使用独立 SQLite 文件、离线模型、检索与故障注入；异常中断是提交前抛出异常的模拟。它们验证业务状态和事务语义，不衡量真实模型回答质量、生产吞吐或外部支付可靠性。

当前没有 PostgreSQL 多实例并发或真实支付集成结果。多实例确认还要求各处理实例使用统一发布的知识版本。历史上游检索和生成数字不属于本次测量。
