# 设计与实现范围

EvidenceFlow 将政策问答、订单核对、处置建议、人工确认和业务验证放在同一个售后工作台，支持取消订单、提交退货申请和提交退款申请。

## 当前实现

| 模块 | 负责的约束 |
|---|---|
| 独立请求运行时 `app/runtime/` | 对话解析、显式路由、新规划协议、订单范围校验、只读调度和引用校验 |
| 工单服务 `app/services/case_service.py` | 持久化提议和证据、确认前复核、条件更新取得执行权、事务内验证、失败回滚和结果复用 |
| 业务网关与对话状态 `app/business/` | 订单适配接口、用户操作与订单槽位、跨重启澄清 |
| 知识生命周期 `app/retrieval/knowledge.py` | 增量构建、向量复用、请求级快照与版本化缓存 |
| 检索协调 `hybrid.py` / `fusion.py` | 并行后端、单路故障处理、去重融合和固定读视图 |
| 工单工作台与评测 | 审核与处理时间线、业务状态裁判、原始轨迹、请求预算和冻结版本重放 |

0.2 替换了旧图执行链、规划与工具基础协议；底层模型与检索适配器、HTTP 与数据库基础组件仍有第三方来源。具体边界见 [版权清单](../THIRD_PARTY_NOTICES.md) 与 [替换清单](../UPSTREAM.json)，不能将全仓库文件统一描述为原创。

## 执行流程

明确操作先形成待审核提议，保存工具参数、订单快照和政策证据。确认时重新核对订单、知识版本与有效期，通过后在本地数据库事务内执行并验证。业务写入、工单完成状态及结果共同提交；失败时回滚。

待审核动作跨服务重启保留，重复确认读取已有结果。多订单请求先澄清，纯咨询只读取信息；模型不能把只读计划变成写调用。订单事实直接来自工具回执，政策答复必须引用当前证据。

## 验证与范围

当前结果见 [0.2 验证记录](../eval/experiments/RUNTIME_V2.md)，旧版本结果见 [实验目录](../eval/experiments/README.md)。已有任务曾用于诊断，当前成绩属于回归，不作为新的泛化准确率。

当前采用客户端声明的演示身份，本地事务不覆盖外部支付或订单系统。知识发布为单进程方案。政策证据由审核人核对，引用可追溯不等于自动完成政策适用性裁决。运行时针对有限售后操作，不提供开放式自主任务循环。
