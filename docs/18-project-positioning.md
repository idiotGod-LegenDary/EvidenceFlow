# 设计与实现范围

EvidenceFlow 将政策问答、订单核对、处置建议、人工确认和业务验证放在同一个售后工作台，支持取消订单、提交退货申请和提交退款申请。

## 模块来源

| 来源 | 内容 |
|---|---|
| Adaptive-rag | FastAPI、LangGraph 工作流、混合检索、精排、规划与工具协议、基础确认和幂等 |
| 知识模块扩展 | 增量解析、向量复用、请求级快照、版本化缓存与引用摘要 |
| 工单模块 | 持久化建议和证据、确认前复核、条件更新取得执行权、事务内验证、失败回滚及结果复用 |
| 对话与界面 | 持久化订单澄清、政策证据传递、工单筛选、审核与处理记录 |
| 评测 | 业务状态裁判、模型与工具轨迹、请求预算、归档版本和受控对照 |

## 执行流程

明确操作先形成待审核建议，保存工具参数、订单快照和政策证据。确认时重新核对订单、知识版本与有效期，通过后在本地数据库事务内执行并验证。业务写入、工单完成状态及执行结果共同提交；失败时回滚本次写入。

待审核动作跨服务重启保留。重复确认已完成动作读取已有结果。多订单请求先澄清选择，纯咨询只读取业务信息和政策。

## 验证

当前和历史结果分别保存在 [实验目录](../eval/experiments/README.md)。P0 对照的完整在线配对为基线 7/14、归档候选 13/14；补修后的版本另有本地回归，不能混用两个版本的成绩。

任务集包含同族改写，在线样本规模有限。实际范围、预算中断及未运行任务见 [P0 验证记录](../eval/experiments/P0_VERIFICATION.md)。

## 范围

当前采用客户端声明的演示身份，本地事务不覆盖外部支付或订单系统。知识发布为单进程方案。政策证据由审核人核对，引用可追溯不等于已经完成政策适用性的自动裁决。
